# 阶段验收标准

## 通用通过规则

一个阶段只有同时满足以下四类证据才算通过：

1. **解释**：不看资料能解释核心概念、输入输出和常见失败。
2. **实现**：能从空文件写出关键最小实现，而非只运行现成 Notebook。
3. **实验**：至少有一次受控对照、指标和错误分析。
4. **迁移**：能把概念映射到机器人学习或现有工程。

状态定义：

- `通过`：四类证据齐全。
- `部分通过`：实现已完成，但解释、实验或迁移不足。
- `未通过`：只能复述或运行现成代码。

## 阶段一：训练闭环

### 必须完成

- 独立实现 PyTorch 分类训练、验证、保存、加载和推理。
- 能检查一个 batch 的 shape、dtype、范围和 device。
- 能定位至少 5 种常见训练错误。
- 在 8GB 显存设备或更严格配置下完成实验。

### 口头检查

- autograd 如何形成计算图？
- 为什么不应在 `CrossEntropyLoss` 前手动 softmax？
- `train()`、`eval()` 和 `no_grad()` 分别做什么？
- batch size 改变时，训练和显存会发生什么？

## 阶段二：经典机器学习

### 必须完成

- 使用 scikit-learn Pipeline 完成表格任务。
- 比较至少三类模型。
- 使用交叉验证并保留独立测试集。
- 明确记录 baseline、指标选择和数据泄漏检查。

### 失败信号

- 只报告最高分。
- 在测试集上反复调参。
- 预处理在划分前使用全体数据拟合。

## 阶段三：视觉

### 必须完成

- 从零实现小型 CNN。
- 使用预训练模型完成迁移学习。
- 进行错误样例分类和至少一次受控改进。
- 提供独立推理脚本。

### 迁移问题

- 机器人相机发生光照、视角或背景变化时，验证集应如何设计？
- 线上误判来自视觉模型还是上游数据时，如何区分？

## 阶段四：Transformer 与大模型

### 必须完成

- 实现 scaled dot-product attention 和 causal mask。
- 训练一个小型字符或 token 语言模型。
- 完成一次 LoRA 或等价参数高效微调实验。
- 记录训练显存、推理显存、速度和结果。

### 口头检查

- attention 中 Q/K/V 的 shape 如何变化？
- causal LM 为什么不能看到未来 token？
- LoRA 改变哪些参数，解决什么约束？
- VLM 和 VLA 在输出空间上有什么根本区别？

## 阶段五：强化学习

### 必须完成

- GridWorld 动态规划。
- CartPole DQN。
- 使用成熟 PPO 实现完成一次训练并追踪核心流程。
- 实现简单 MPC/CEM 规划实验。

### 口头检查

- supervised learning 与 RL 的数据分布有何区别？
- replay buffer 和 target network 为什么有用？
- on-policy 和 off-policy 的主要代价是什么？
- model bias 为什么会伤害长 rollout？

## 阶段六：机器人策略

### 必须完成

- 审计至少一个机器人数据集。
- 能追踪 ACT 或 Diffusion Policy 的训练数据流。
- 跑通一个小型策略训练或评估任务。
- 比较逐步 BC、action chunk 和 diffusion/flow action。

### 数据审计项

- observation/action shape。
- 采样频率与时间对齐。
- 归一化统计量来源。
- episode 划分与潜在数据泄漏。
- train/eval 场景是否真正独立。

## 阶段七：综合工程

### 必须完成

- 清晰的问题定义和验收指标。
- 可复现的数据与训练入口。
- baseline、受控改进和错误分析。
- 独立推理入口。
- 至少一个目标设备性能结果。
- README、架构图、限制和失败案例。

## 补课规则

验收不通过时只补缺失证据：

- 解释不足：闭卷画图并口述，不重复刷整套课程。
- 实现不足：从空文件重写最小版本。
- 实验不足：增加单变量对照和错误样例。
- 迁移不足：选择一个现有机器人项目，写出对应的数据流和风险。
