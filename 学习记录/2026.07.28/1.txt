3. 类定义
class DiffusionPolicy(nn.Module):

它继承了 nn.Module。

这意味着 DiffusionPolicy 可以获得 PyTorch 模型的标准能力，例如：

policy.to(device)
policy.train()
policy.eval()
policy.parameters()
policy.state_dict()

这很重要，因为 Trainer 会调用：

self.policy.to(device)
self.policy.train()

Optimizer 也需要：

policy.parameters()

假如 DiffusionPolicy 不继承 nn.Module，这些机制就不能自然工作。

4. 初始化方法

源码：

def __init__(
    self,
    vision_encoder,
    state_encoder,
    network,
    scheduler,
    dims
):
    super().__init__()

    self.vision_encoder = vision_encoder
    self.state_encoder = state_encoder
    self.network = network
    self.scheduler = scheduler
    self.dims = dims

这个初始化函数没有自己创建任何具体网络，而是从外部接收已经构建好的组件。

这些组件来自：

src/builder/policy_builder.py

对应关系是：

policy = DiffusionPolicy(
    vision_encoder=vision_enc,
    state_encoder=state_enc,
    network=noise_network,
    scheduler=scheduler,
    dims=dims,
)

也就是说，Builder 负责“造零件”，Policy 负责“使用零件”。

每个组件分别做什么？
vision_encoder
self.vision_encoder = vision_encoder

接收机器人看到的图像：

[B, obs_horizon, C, H, W]

输出视觉特征：

[B, obs_horizon × vision_feature_dim]

例如源码注释中的：

输入：[8, 2, 3, 32, 32]
输出：[8, 2 × 256]
state_encoder
self.state_encoder = state_encoder

接收机器人状态，例如关节位置：

[B, obs_horizon, state_dim]

输出状态特征：

[B, obs_horizon × state_feature_dim]

例如：

输入：[8, 2, 7]
输出：[8, 2 × 64]
network
self.network = network

这是扩散模型中真正负责预测噪声的神经网络。

当前项目使用的是：

DiffusionMLP

它接收：

带噪动作
+ diffusion timestep
+ observation condition

输出：

预测噪声

要特别注意：

DiffusionPolicy 是完整算法，而 network 只是其中负责预测噪声的神经网络。

scheduler
self.scheduler = scheduler

Scheduler 负责扩散过程中的数学规则。

训练时：

scheduler.add_noise(...)

给真实动作添加指定程度的噪声。

推理时：

scheduler.step(...)

从当前噪声动作中逐步去噪。

它不负责学习参数，而是负责控制扩散过程。

dims
self.dims = dims

它保存各部分展开后的维度，例如：

flat_action_dim
flat_vision_dim
flat_state_dim

假设：

pred_horizon = 4
action_dim = 8

那么：

flat_action_dim = 4 × 8 = 32

这样代码就不用在多个地方重复计算维度。

5. 为什么这些模块必须赋值给 self？

例如，为什么不能只写：

vision_encoder = vision_encoder

而必须写：

self.vision_encoder = vision_encoder

一个重要原因是：当一个 nn.Module 被赋值为另一个 nn.Module 的成员时，PyTorch 会自动注册它。

也就是：

self.vision_encoder = vision_encoder
self.state_encoder = state_encoder
self.network = network

这些子模型会自动成为 DiffusionPolicy 的子模块。

因此：

policy.parameters()

会自动收集：

vision_encoder 的参数
+ state_encoder 的参数
+ network 的参数

同理：

policy.to("cuda")

会把这些子模块全部搬到 GPU。

可以把结构理解成：

DiffusionPolicy
├── vision_encoder
├── state_encoder
└── network

而 Scheduler 很可能没有可训练参数，所以它主要作为算法组件存在。

6. 训练入口 compute_loss

接下来是这个文件最重要的方法：

def compute_loss(self, batch):

整体流程可以先压缩成：

从 batch 取数据
    ↓
编码图像和机器人状态
    ↓
生成随机噪声和随机时间步
    ↓
给真实动作加噪
    ↓
网络预测噪声
    ↓
预测噪声和真实噪声计算 MSE

对应源码的五个阶段：

# 1. 准备数据
# 2. 编码条件
# 3. 动态生成已知 noise
# 4. 网络预测
# 5. Loss
7. 第一阶段：从 batch 中取数据
actions = batch['action']
img = batch['img_global']
qpos = batch['robot_qpos']
B = actions.shape[0]

这个 batch 就是 Trainer 从 DataLoader 中拿到的：

for batch in self.dataloader:
    loss = self.policy.compute_loss(batch)

其中：

actions = batch['action']

是真实动作序列，即训练目标。

形状：

[B, pred_horizon, action_dim]

源码给出的例子是：

[8, 4, 8]

含义分别是：

8：batch size
4：预测未来 4 个时间步
8：每一步动作有 8 个维度
img = batch['img_global']

是历史图像观测，形状：

[B, obs_horizon, C, H, W]

例子：

[8, 2, 3, 32, 32]

表示：

8 个样本
每个样本包含 2 帧历史图像
每帧 3 个颜色通道
图像尺寸为 32 × 32
qpos = batch['robot_qpos']

是历史机器人状态，形状：

[B, obs_horizon, state_dim]

例如：

[8, 2, 7]

表示每个样本包含最近两个时间步的机器人状态，每步状态是 7 维。

B = actions.shape[0]

取出 batch size。

后面生成随机时间步和 reshape 都需要这个值。

8. 第二阶段：编码观测条件
vision_feat = self.vision_encoder(img)
state_feat = self.state_encoder(qpos)

图像和机器人状态不能直接与动作拼接，因为：

图像是五维张量；
状态是三维张量；
动作网络需要固定长度的特征向量。

因此先分别编码。

数据流是：

img
 ↓ vision_encoder
vision_feat

qpos
 ↓ state_encoder
state_feat

然后：

global_cond = torch.cat(
    [vision_feat, state_feat],
    dim=-1
)

沿最后一个维度拼接。

假设：

vision_feat：[8, 512]
state_feat：[8, 128]

那么拼接后：

global_cond：[8, 640]

global_cond 的含义是：

对当前机器人所处环境和自身状态的综合描述。

它是扩散模型的条件信息。

没有这个条件，模型只能无条件地产生动作；有了条件，模型才能根据图像和机器人状态预测合适的动作。

9. 第三阶段：生成训练目标噪声
noise = torch.randn_like(actions)

它生成一个与真实动作形状完全相同的高斯噪声：

actions：[B, pred_horizon, action_dim]
noise：  [B, pred_horizon, action_dim]

例如二者都是：

[8, 4, 8]

randn_like 生成的每个值近似来自标准正态分布：

N(0, 1)

接下来随机选择扩散时间步：

t = torch.randint(
    0,
    self.scheduler.timesteps,
    (B,),
    device=actions.device
)

假设：

scheduler.timesteps = 100
B = 8

可能得到：

t = [5, 72, 13, 99, 42, 8, 56, 21]

这里有一个非常关键的设计：

同一个 batch 中的每条样本，可以处在不同的噪声程度。

例如：

样本 1：t=5，只有少量噪声
样本 2：t=72，噪声很多
样本 3：t=99，几乎接近纯噪声

这样模型才能学习各种噪声阶段的去噪任务。

然后：

noisy_actions = self.scheduler.add_noise(
    actions,
    noise,
    t
)

Scheduler 根据时间步 t 将噪声加入真实动作。

概念上可以理解为：

noisy_action
    =
保留一部分真实 action
    +
加入一部分 noise

时间步越大，一般噪声比例越高。

数据流：

真实动作 actions
+ 已知噪声 noise
+ 随机时间步 t
        ↓
scheduler.add_noise()
        ↓
带噪动作 noisy_actions

特别重要的是：这里的噪声是代码自己生成的，所以它是已知答案。

因此网络的训练任务就是：

输入带噪动作
预测刚才加入的 noise
10. 第四阶段：展开动作

源码：

noisy_flat = noisy_actions.view(B, -1)

原始形状：

[B, pred_horizon, action_dim]

展开后：

[B, pred_horizon × action_dim]

例如：

[8, 4, 8]
    ↓
[8, 32]

因为当前噪声网络是 MLP，所以需要将时间维和动作维展平。

源码第 43 行的注释写成了：

(8, 28)

这与前面的：

pred_horizon=4
action_dim=8

不一致。正确结果应该是：

4 × 8 = 32

所以这里是注释错误，不是代码计算错误。

11. 网络预测噪声
pred_noise = self.network(
    noisy_flat,
    t,
    global_cond
)

输入包括三个部分：

noisy_flat：现在这条动作被污染成什么样
t：当前污染到了哪个程度
global_cond：机器人现在看到了什么、处于什么状态

输出：

pred_noise

形状应为：

[B, pred_horizon × action_dim]

例如：

[8, 32]

为什么一定要告诉网络 t？

因为同一个 noisy_action 在不同时间步下代表的噪声程度不同。网络必须知道当前处于哪个扩散阶段，才能判断应该去掉多少噪声。

12. 第五阶段：计算 Loss

最后：

return F.mse_loss(
    pred_noise,
    noise.view(B, -1)
)

真实噪声原本形状是：

[B, pred_horizon, action_dim]

先展开为：

[B, pred_horizon × action_dim]

这样才能和：

pred_noise

形状一致。

训练目标是：

网络预测的噪声 ≈ 代码实际加入的噪声

因此使用均方误差：

MSE(pred_noise, true_noise)

Loss 越小，说明网络越能识别动作中加入的噪声。
