## 闭卷题答案

1. `[32, 3, 224, 224]` 表示 batch size、channel、height、width。
2. `[16, 10] @ [10, 4]` 的结果是 `[16, 4]`。矩阵乘法的中间维度 `10` 必须匹配，输出保留两侧的外部维度 `16` 和 `4`。
3. 同一运算中的 tensor 必须位于兼容的设备上，否则 PyTorch 无法直接调度 CPU 与 CUDA 之间的计算。
4. 多分类标签通常使用 `torch.int64`，尤其是配合 `CrossEntropyLoss` 时。`int8` 的数值范围虽可能够用，但不是该损失函数的标准标签 dtype。
5. `[B, T, C, H, W]` 中的 `T` 表示时间序列长度，例如连续观察帧的数量。

## 概念补充

- `torch.arange` 生成等间隔的一维数值序列；`torch.arange(12)` 生成 `0` 到 `11`，不包含 `12`。
- `reshape` 改变形状但保持元素总数不变。
- `transpose` 交换指定的两个维度；`permute` 可以一次指定任意维度顺序。
- `view` 是更严格的 reshape，要求内存布局满足连续性条件；初学阶段优先使用 `reshape`。
- `float32` 精度较高、显存占用较大；`bfloat16` 指数范围接近 `float32`，更适合深度学习混合精度，但尾数精度较低。
- `product + bias` 使用 broadcasting：`product` 的 shape 是 `[2, 4]`，`bias` 的 shape 是 `[4]`，PyTorch 将 bias 视为每一行都使用同一个 `[4]` 向量。
- `tensor.mean()` 表示 tensor 中元素的平均值；`tensor.std()` 表示元素围绕平均值的波动程度。`batch_size` 是一个数量，不是存放数据的 tensor，通常应对 `batch` 调用这两个方法。

对于随机图像 batch，`mean` 接近 0、`std` 接近 1，是因为数据由 `torch.randn` 生成，目标分布近似标准正态分布。真实图像数据不一定如此，是否正常要结合数据预处理方式判断。

## 纠错记录

第 3 题最初误判为合法。判断广播时必须从最后一维开始，而不是先看第一个维度是否相同。

## Day 2 概念澄清

### 批量矩阵乘法

- `[2, 3, 4] @ [2, 4, 5] -> [2, 3, 5]` 是第 0 批与第 0 批相乘、第 1 批与第 1 批相乘，批次之间互不混合。
- 若某个批次维度为 `1` 或不存在，它可以广播到另一侧的批次维度，例如 `[2, 3, 4] @ [4, 5]` 会把同一个 `[4, 5]` 矩阵用于所有批次。
- 批量矩阵乘法真正做矩阵乘法的是最后两个维度；前面的维度属于 batch 维度，需要满足相等、为 `1` 或不存在。

### 广播中的 1 和不存在

- 维度为 `1`：该维度可以扩展到另一侧对应的长度，例如 `[2, 3, 4] + [1, 4]` 将 `[1, 4]` 视为 `[1, 1, 4]`，再广播到 `[2, 3, 4]`。
- 维度不存在：低维 tensor 会在左侧概念性补 `1`，例如 `[4]` 参与 `[2, 3, 4]` 运算时可视为 `[1, 1, 4]`。
- 广播通常不需要真的复制数据，而是通过 stride 规则让同一数据参与多个位置的计算。

## 今日目标

2. 手写均方误差 `MSE`。
3. 手写参数梯度和梯度下降更新。
4. 观察学习率对训练过程的影响。

## 运行方式

```bash
python exercises/day03_linear_regression_numpy.py
```

## 问题定义

我们构造一组近似满足下面关系的数据：

```text
y = 3x + 2 + noise
```

模型不知道真实的 `3` 和 `2`，只知道自己要学习一个：

```text
prediction = weight * x + bias
```

其中：

- `weight`：斜率。
- `bias`：截距。
- `prediction`：模型预测。
- `target`：真实标签。

## 训练循环

```text
初始化 weight、bias
    ↓
根据当前参数预测
    ↓
计算 MSE loss
    ↓
计算 d_weight、d_bias
    ↓
参数减去 learning_rate × gradient
    ↓
重复多个 epoch
```

## 核心公式

模型：

\[
\hat{y} = wx + b
\]

均方误差：

\[
L = \frac{1}{N}\sum_i(\hat{y}_i-y_i)^2
\]

梯度：

\[
\frac{\partial L}{\partial w}
= \frac{2}{N}\sum_i(\hat{y}_i-y_i)x_i
\]

\[
\frac{\partial L}{\partial b}
= \frac{2}{N}\sum_i(\hat{y}_i-y_i)
\]

更新：

\[
w \leftarrow w-\eta\frac{\partial L}{\partial w}
\]

\[
b \leftarrow b-\eta\frac{\partial L}{\partial b}
\]

其中 `eta` 是 learning rate。

## Day 3 闭卷题

1. 为什么参数更新要减去梯度，而不是加上梯度？
2. 如果 loss 持续变大，learning rate 可能有什么问题？
3. `weight` 和 `bias` 为什么都需要单独的梯度？
4. 为什么 MSE 中要对所有样本的误差求平均？
5. 这段 NumPy 代码中，哪几部分将来会被 PyTorch 的自动求导和 optimizer 替代？

## Day 3 首轮答案与实验

1. 梯度指向 loss 增长最快的方向，因此参数沿负梯度方向更新，以降低 loss。
2. loss 持续变大通常说明学习率可能过大，也可能存在梯度、数据尺度或公式实现错误，不能只归因于学习率。
3. `weight` 和 `bias` 在前向计算中的作用不同，对 loss 的影响不同，因此需要分别计算梯度。
4. MSE 取平均可以避免 loss 和梯度简单随样本数增加而增大，并便于比较不同 batch 或数据集规模的实验。
5. PyTorch autograd 会替代手动梯度公式，optimizer 会替代手动参数更新；模型预测和 loss 仍然需要由我们定义。

### 实验解释

`learning_rate=0.5` 在本例中没有发散，是因为数据尺度简单、模型只有两个参数、MSE 对线性模型形成简单的凸优化问题。不能把这个结果推广为“0.5 总是合适”；换数据尺度、模型或损失函数后，它可能震荡或发散。

## 运行方式

```bash
python exercises/day04_autograd.py
```

## 核心概念

### `requires_grad=True`

```python
weights = torch.zeros(2, requires_grad=True)
```

表示 PyTorch 需要记录涉及 `weights` 的运算，并在反向传播时计算它的梯度。

### `grad_fn`

由其他 tensor 运算得到的结果通常带有 `grad_fn`，它表示该结果如何由前面的运算产生，是计算图的一部分。

### `loss.backward()`

从 loss 开始沿计算图反向传播，使用链式法则计算所有需要梯度的叶子 tensor 的 `.grad`。

### 梯度清零

PyTorch 默认会累积梯度：

```python
loss.backward()
loss.backward()
```

第二次结果会加到第一次的 `.grad` 上。因此每个训练 step 通常需要：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

手写 tensor 时可以使用：

```python
weights.grad.zero_()
```

## Day 4 闭卷题

1. 为什么输入 `features` 通常不需要 `requires_grad=True`，而模型参数需要？
2. `loss.backward()` 之后，梯度存在哪里？
3. 为什么训练循环不能忘记 `zero_grad()`？
4. `torch.no_grad()` 适合训练还是推理？为什么？
5. 如果一个 tensor 的 `requires_grad=False`，它还能参与模型前向计算吗？

## Day 4 闭卷答案

1. 输入数据通常不需要更新，模型参数需要通过梯度更新，因此只对模型参数追踪梯度。
2. `loss.backward()` 后，梯度通常存储在需要梯度的叶子 tensor 的 `.grad` 属性中，例如 `weights.grad` 和 `bias.grad`。
3. 梯度默认累积；不清零会让上一个 batch 的梯度影响当前 batch 的参数更新。
4. `torch.no_grad()` 主要用于推理和验证，因为它关闭该代码块中的 autograd 记录，减少计算图和显存开销；它本身不等于修改参数。
5. `requires_grad=False` 的 tensor 仍然可以参与前向计算，只是不为它保存反向传播所需的梯度。
