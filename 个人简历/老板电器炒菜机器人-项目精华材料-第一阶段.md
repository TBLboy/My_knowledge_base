## 1. 项目定位

面向炒菜机器人“抓锅并将锅内食材倾倒入餐盘”的任务，参与构建从感知目标、手眼标定、抓取点计算、灵巧手控制、准备倾倒、倾倒执行、放锅回位到失败接管的机器人任务闭环。

项目采用 V1/V2 分阶段策略：

- V1：左手单臂、固定场景、无抓取确认的基础闭环。
- V2：右手锅铲辅助和后续抓取确认能力。
- 生产级泛化、全轨迹自适应力控和未经验证的双臂协同不作为当前 V1 承诺。

## 3. 任务链路

```text
感知锅具/锅把
  → 统一中心坐标系与抓取点计算
  → 抓取 TCP 目标
  → 左手张开并到达起始位
  → 抓锅并闭手
  → 提锅到准备倾倒位
  → 两段接近/倾倒轨迹执行
  → 放锅到固定点
  → 张手并回 home
```

与系统其他模块的边界：

- 感知链路发布锅把、锅尖/端点和餐盘相关目标。
- Policy 负责根据业务状态决定下一阶段动作。
- Skill 负责将阶段动作拆成可执行的运动原语。
- Executor/Driver 负责 ROS2 Action、关节/笛卡尔运动和底层控制。
- 底盘移动和感知模型属于外部团队/模块依赖，不应在简历中全部归为个人交付。

## 4. 核心技术动作

### 4.1 自包含 PanPourSkill

记录中已确认 V1 正式版本采用单一自包含 `PanPourSkill`，不依赖临时 teach 链路。

Skill 覆盖：

- `home_open`：回到抓锅起始点并张手。
- `move_cartesian`：抓取、提锅和准备倾倒等普通笛卡尔移动。
- `close_hand`：使用锅具抓取预设下发手指角度和力矩。
- `pour_delta_replay`：执行增量法兰轨迹回放。
- `put_fixed`：移动到固定放锅点。
- `open_hand`：释放锅具。
- `return_home`：回到 home 位姿。

自包含资源包括固定点位、手部预设、轨迹 manifest 和增量倾倒轨迹，减少动作参数散落在 Policy、Planner 和 Executor 多处硬编码的问题。

### 4.2 Policy/Skill 状态推进

- Policy 维护当前阶段、步骤索引、待发送步骤和左臂忙状态。
- 每个阶段只允许一个左臂 Goal 在途。
- Goal 成功后才推进到下一阶段。
- Goal 失败进入统一错误路径，不静默跳过阶段。
- 任务结束后清理 Policy 上下文。
- 取消、急停和硬件保护沿用现有 Executor/Driver 机制。

这一部分可体现你对机器人任务执行系统中**状态机、异步 Goal、资源独占和失败传播**的理解。

### 4.3 两段接近运动

为降低直接移动到最终倾倒姿态的风险，PanPourSkill 采用两段接近：

1. 先移动到最终法兰目标上方约 5 cm 的安全预接近位置 `b`。
2. 再下降到最终目标 `a`。
3. 通过现有 `/robot_driver/move_cartesian` 执行。

当前记录确认本地视觉测试脚本已复刻并离线验证两次 MoveL 的顺序、位姿和速度；正式硬件移动仍需按 dry-run → 实机方式验证。

### 4.4 增量法兰轨迹回放

- 使用录制的法兰轨迹生成 delta 资产。
- 运行时读取当前法兰位姿。
- 将 delta 展开为当前起点下的完整目标轨迹。
- 转换为 SDK IK 所需的 end/ref 目标。
- 对完整轨迹预先计算 IK。
- 检查关节限位和相邻解连续性。
- 全部通过后复用 MoveAbsJ 批量回放。

记录同时识别了边界：delta 轨迹保证相对运动形式，但不能保证任意起点下都可达；起点变化可能触发关节限位、IK 分支或奇异性问题。因此后续表达应写“实现并验证增量轨迹回放及可达性预检”，不能写成“任意起点泛化回放已解决”。

### 4.5 手眼标定与抓取目标

- 处理左右臂手眼标定和标定文件迁入主仓库规范目录。
- 根据锅具抓取点加可调偏置计算左臂 TCP 抓取目标。
- 将感知坐标、中心坐标系、机械臂 base、flange 和 TCP 语义统一。
- 记录左右臂标定质量检查、中心坐标系计算和抓取点三轴微调参数。
- 右臂手眼标定已有成功记录；左臂用于抓锅闭环的 TCP 标定也有实机结果记录。

### 4.6 感知链路适配

- 针对 `boss_kitchen_scene2` 模型类别和置信度阈值进行离线图片验证。
- 识别锅把/锅尖端点类别与当前模型输出不匹配的问题。
- 记录 `plate_center` 尚未由感知后处理输出的接口缺口。
- 新增 PanPour 感知适配层，将场景对象转换为 `PanPourPolicy.update_handle_detection()` 所需的中心点与方向信息。
- 感知无效时保持 Policy 等待，不使用不完整目标强行执行抓取。

### 4.7 SDK 兼容与坐标换算排查

- 识别控制器 xCore 版本与 PC 端 Python SDK 版本的最低要求不匹配。
- 将 SDK 回退到可连接当前控制器的 `xcoresdk_python-v0.5.1.ar_12`。
- 更新主工程、GUI、执行仓库和本地工具中的 SDK 路径引用。
- 修复左臂视觉脚本中 planner 输出法兰目标直接传给 SDK 的坐标换算问题。
- 按 `pose_frame_rot_x_deg=-90°` 完成坐标补偿，并通过 `EndInRefToFlanInBase` 转回 flange 语义。
- 兼容 `robot.baseFrame(ec)` 返回对象和 6 元素列表两种 SDK 形态。
- 通过 compileall、离线数值验证和 monkeypatch 验证 IK 与 MoveL 下发目标。

## 5. 工程难点与解决方向

| 难点 | 记录中的解决方向 |
| --- | --- |
| 抓锅动作涉及锅具、手、臂和底盘多个边界 | 先冻结 V1 左手单臂闭环，V2 预留右手锅铲和抓取确认 |
| 固定点位和轨迹资源散落风险 | 采用自包含 PanPourSkill 和 resource manifest |
| 直接到最终目标可能产生碰撞/姿态风险 | 采用上方预接近点到最终点的两段接近 |
| 录制轨迹不能直接保证新起点可达 | 运行时展开 delta、全轨迹 IK 预检和关节连续性校验 |
| 感知模型类别/端点不稳定 | 先离线验证模型输出，再设计适配层和等待机制 |
| SDK 版本不兼容 | 根据控制器版本回退可兼容 SDK，并清理路径引用 |
| 左臂坐标转换错误 | 对齐正式 driver 链路的坐标补偿和 flange 语义 |
| 底盘接口未完全启用 | 记录底盘后端配置依赖，不把未验证的底盘动作写成已完成 |
