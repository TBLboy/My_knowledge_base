## 1. 项目定位

面向机器人自动切豆腐任务，构建从视觉感知、目标几何计算、刀具预备、运动学求解、切削执行、人工旋转到多阶段流程结束的完整机器人任务闭环。

项目不是单一的“切割动作脚本”，而是一套包含感知、状态处理、任务编排、动作服务器、机器人适配器和底层控制接口的 ROS2 工程。

## 3. 系统架构与运行链路

```text
RealSense
  → SAM3 分割
  → pose_estimator 估计物体位姿
  → tofu_state_node 稳定化、健康状态和几何特征
  → phase_manager_node 多阶段状态机
  → knife_prepare_action_server / knife_cut_action_server
  → xcore/lbot arm adapter
  → ROS2 robot services
  → 机械臂与刀具执行
```

主要分层：

1. **感知层**
   - SAM3 检测/分割豆腐。
   - 深度与 mask 融合，估计 6D 物体姿态。
   - 输出 `ObjectStateArray` 等结构化目标状态。
2. **状态处理层**
   - 对视觉结果进行滑动窗口过滤。
   - 维护 tracking/stale/lost 等健康状态。
   - 从豆腐顶面四角、边方向和高度计算稳定的 `TofuState`。
3. **任务编排层**
   - 7 阶段状态机管理取刀后的连续切割流程。
   - 通过异步 Action 调用准备位姿和切割动作。
   - 处理人工旋转、继续信号、失败和阶段重入。
4. **动作层**
   - `knife_prepare_action_server`：计算并执行视觉引导的刀具预备位姿。
   - `knife_cut_action_server`：执行多轮切割、回撤、步进、垂直切割和推压。
5. **机器人适配层**
   - 封装 IK/FK、TCP offset、关节运动、笛卡尔路径和到位验证。
   - 通过 ROS2 service 调用 xCore/Lbot 控制器。

## 4. 核心业务流程

```text
系统初始化
 → 取刀完成
 → 第一次预备
 → 第一次水平切割
 → 人工旋转豆腐
 → 第二次预备
 → 第二次水平切割
 → 再次人工旋转
 → 垂直切割预备
 → 第三次垂直切割
 → 结束
```

工程记录还包含完整的 Phase 4/6 回位和等待机制：

- 切割完成后沿累计步进方向安全回撤。
- 回到等待姿态。
- 等待操作员旋转豆腐并发出继续信号。
- 使用对应配置重新进入视觉准备阶段。

## 5. 关键技术动作

### 5.1 从视觉目标计算刀具 TCP

没有直接使用豆腐中心点作为刀具目标，而是：

1. 获取豆腐顶面四个角点。
2. 选择右侧边的两个角点并计算边方向。
3. 计算右侧边中点。
4. 在顶面 XZ 平面内构造垂直偏移方向。
5. 根据水平偏移量和顶面高度生成刀具 TCP 位置。
6. 根据刀脊方向、刀面倾角和边对齐模式生成 TCP 姿态。

该方案将“检测到物体”转化为“可用于切割的刀具几何目标”，比使用目标中心点更接近真实刀具动作需求。

### 5.2 IK/FK 候选搜索与安全评分

预备位姿不是直接调用一次 IK，而是：

- 生成多个候选刀具姿态/关节解。
- 通过 FK 或切割预览验证候选结果。
- 过滤违反关节安全余量的解。
- 综合关节限位余量、路径平滑性和当前姿态距离进行评分。
- 选择可执行且风险较低的准备姿态。

工程记录中明确了至少 15° 的关节安全余量约束，避免“数学上有解、真实运动不安全”的问题。

### 5.3 TCP 与法兰坐标抽象

- 刀具 TCP 相对法兰是固定纯平移 offset。
- 上层视觉和动作逻辑使用 TCP 坐标。
- 机器人适配器统一完成 TCP ↔ 法兰转换。
- FK 返回 TCP 位姿，IK 将 TCP 目标转换为法兰目标。
- 上层不需要重复处理工具偏置，降低坐标混用风险。

### 5.4 切割轨迹与阻抗控制

切割过程采用多轮原子动作：

```text
沿切割方向运动 → 回撤 → 沿步进方向移动 → 下一轮切割
```

- 水平切割由多个 cycle 组成。
- 垂直切割增加中段推压和尾段推压逻辑。
- 切割优先使用阻抗模式。
- 阻抗失败时回退到位置模式。
- Phase 7 按 segment 级别处理回退，避免整阶段重试时从错误锚点重新开始。

### 5.5 xCore / Lbot 迁移

记录中包含从 xCore 版本向 Lbot 版本的适配工作：

- 抽象机械臂适配器，封装 IK、FK、移动和到位验证。
- 识别并处理 xCore 与 Lbot 的坐标系差异。
- 通过实际硬件验证 Euler 角约定，最终确认 Lbot 使用外旋 ZYX 约定。
- 将几何计算、状态机和机器人控制适配层解耦，减少平台迁移影响。
- 删除对 URDF 离线 IK 的不必要依赖，改用 Lbot 内置 IK 能力。

### 5.6 阶段通信与人工介入

- 感知采用 ROS2 Topic 持续发布。
- 准备与切割采用 Action Client/Server 异步调用。
- 机器人底层通过 ROS2 Service 请求状态、关节移动和笛卡尔路径。
- Phase 4/6 通过终端输入或文件信号等待人工旋转。
- 抓刀迁移方案使用生命周期 wrapper、独立子进程和单 topic 完成资源隔离，避免旧视觉管线污染新阶段。

## 6. 工程难点与解决方向

| 难点 | 解决思路 |
| --- | --- |
| 视觉中心点不能直接作为刀具目标 | 基于顶面四角和边方向重建 TCP 几何目标 |
| IK 数学可解但运动不安全 | 增加关节安全余量、候选评分和切割预览 |
| TCP/法兰/相机坐标容易混用 | 在适配器统一封装 TCP offset 与坐标转换 |
| 阻抗动作偶发失败 | 增加位置模式回退，并按 segment 控制重试边界 |
| 人工旋转导致流程断裂 | 设计 Phase 4/6 等待节点和可恢复的阶段重入 |
| xCore 与 Lbot API/坐标约定不同 | 通过适配器隔离平台差异，并用实机确认 Euler 约定 |
| 视觉资源在阶段切换时互相干扰 | 通过生命周期包装和独立子进程隔离资源 |
| 离线逻辑与真机运动不一致 | 用 ROS2 接口、预览、FK 验证和硬件测试逐层验收 |
