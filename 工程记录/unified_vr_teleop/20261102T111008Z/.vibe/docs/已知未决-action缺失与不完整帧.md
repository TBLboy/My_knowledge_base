# 已知未决：action 缺失与不完整帧

- 日期：2026-11-02
- 状态：**临时安全策略已实施，正式策略未定**
- 关联基线：`hdf5-recording-final-baseline` v1.0（这两项被显式列为暂缓）
- 触发：真机测试前评估，若按“缺失即拒绝导出”，一次 hold 或掉线就会让整条数据无法导出。

## 问题 1：action 在部分帧缺失

### 现象

`/action` 是 `(T, N)` 的定长数组，行数必须与 `/timestamp` 一致。但下列情况会让某些帧没有 action：

- 录制开始后、第一次下发目标之前；
- 操作员短按菜单暂停；
- XR 输入超过 150ms 不新鲜；
- 目标流 200ms 未更新 / 租约 500ms 超时；
- adapter 报错后 hold；
- 复位期间（当前复位前先停录制，属异常路径）。

### 约束

基线禁止三种做法：

1. 补零占位；
2. 由 recorder 复制上一帧；
3. 用实测 EEF 冒充 action。

### 当前代码行为（临时安全策略）

- adapter 只在**实际保持目标**时上报 action；否则该帧 action 为空；
- 中间层如实记录，不做补齐；
- **录制开头的前缀**：首次 action 之前的帧以 state-only 记录；导出时把这段前缀从时间轴、视频和遥测中一并裁掉，`/action` 仍然每行都有真实值；
- **首次 action 之后的空档**：导出抛 `ExportError` 并保留原始会话，不生成 HDF5。

裁剪只改变导出的 HDF5，原始 MP4 和 `recording_frames.json` 保持完整。

### 契约违规与"缺数据"必须分开处理（2026-11-02 补）

此前两者都走同一条「整帧丢弃」路径，导致 1 秒录制的 bug：`gripper` 未登记进 action 白名单，`build()` 对**每一帧**抛错，于是首次 action 之后的帧全部被丢弃，而丢弃计数没有写进 meta，产出的 HDF5 反而看起来是干净的。

现在的分工：

| 情况 | 处理 | 可见性 |
| --- | --- | --- |
| 声明的字段确实缺失 | 丢弃整帧（本策略） | `sync_skipped_incomplete` 写入 meta |
| adapter 破坏字段契约（代码 bug） | **保留视频和时间戳**，不写标准遥测 | `telemetry_errors` + `telemetry_warning` 写入 meta；导出直接拒绝 |

契约违规绝不能靠丢帧掩盖：视频与数据集长度一旦不一致，导出必须在 `require_standard_coverage` 处失败，而不是静默产出短文件。

### 影响

真机录制中一旦在首次跟随之后出现 hold / 暂停 / 遥测超时，该 episode 无法导出。数据不会损坏，但也拿不到训练格式。

### 候选正式策略

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A（推荐） | 缺 action 的整帧不写入 HDF5（图像/状态一并跳过），timestamp 保留真实间隔 | HDF5 不含暂停期间的图像与状态 |
| B | 保留帧，新增 action 有效性表达或独立 action 时间轴 | 需修改基线，与「不新增 per-frame mask」冲突 |
| C | 录制中进入非保持状态即自动结束 episode | 打断操作员流程 |

## 问题 2：不完整帧

### 现象

相机或遥测在某一段时间不可用：

- 三路相机缺一路，或同步帧组不完整；
- 相机正常但机器人实测状态超时；
- 双臂只有一侧有效。

### 当前代码行为（临时安全策略）

- 缺相机：该帧 `aligned=False` 时整个 triplet 不产出（不再生成黑色占位图）；
- 缺遥测：该帧 `arm=None`，标准帧不写入；
- 导出时若「已声明字段在部分帧缺失」，抛 `ExportError`。

### 影响

同上：录制中途掉一次线，整条 episode 无法导出。

### 候选正式策略

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A（推荐） | 不完整帧整帧跳过，timestamp 保留真实间隔 | 该时段图像/状态不进入 HDF5 |
| B | 保留完整信号、缺失信号留空 | 需要长度不一致的表达方式，与"行数对齐"冲突 |
| C | 直接判 episode 异常，人工决定 | 依赖人工质检流程（自检与拒收也暂缓） |

## 临时策略（2026-11-02 已实施，正式策略未定）

为支持真机测试，代码采用「**宁可少存，也不伪造**」的安全默认；用户确认后需替换。

### 问题 1：action 在部分帧缺失

| 场景 | 当前行为 |
| --- | --- |
| 录制开头、首次下发目标之前 | 该段以 state-only 帧记录；导出时**连同视频一起裁掉这段前缀**，使 `/action` 每一行都有真实值 |
| 首次 action 之后出现空档（hold / 暂停 / 超时） | **拒绝导出**，`h5_status=failed`，保留原始会话 |
| 整条 episode 从未有 action | 正常导出 state-only，`has_action=false`，不创建 `/action` |

裁剪只发生在导出阶段，原始 MP4 与 `recording_frames.json` 不被修改。

### 问题 2：不完整帧

| 场景 | 当前行为 |
| --- | --- |
| 同步帧组未对齐（缺相机 / bracket 失败） | 该帧不产出，不生成黑色占位图 |
| 遥测缺失或过期 | 该帧不写入标准帧；在录制侧按 `require_complete_frames` 整帧丢弃并计数 `skipped_incomplete` |
| 已声明字段在部分帧缺失 | 导出抛 `ExportError`，保留原始会话 |

开关：`config/config.yaml` 里 `recording.require_complete_frames`（默认 `true`）。设为 `false` 只用于排查，不改变导出时的拒绝行为。

### 仍然会失败的情况

- 首次 action 之后出现任何空档 → 导不出；
- 任意一帧缺已声明观测字段 → 导不出。

真机测试若遇到导出失败，先看 `meta.json` 的 `h5_error` 与 `skipped_incomplete` 计数。


## 需要用户决定的事项

1. action 缺失与不完整帧是否统一采用「整帧跳过」；
2. 跳过是否需要在 episode 元数据里体现（例如记录被跳过的时段）；
3. 跳过后是否影响 batch 完整性判断。

在确认前，本文件与 `hdf5-recording-final-baseline` v1.0 第 7、8 节共同生效：临时策略不得被当成已批准的业务规则。
