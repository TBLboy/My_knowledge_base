# 统一采集管线架构设计

- 日期：2026-11-02
- 依据：`.vibe/requirements/hdf5-recording-final-baseline.md` v1.0
- 目标代码：`unified_vr_teleop_franka/Dagger_web`
- 状态：设计已定，实现按任务依次推进

## 1. 现状与目标差距

现行链路：

```text
FrankaController ─► FrankaAdapter ─► DeviceWorker ─► Client(socket)
                                                        │
                                        FrankaArmManager┴─► TelemetryBuffer
                                                                │
相机驱动 ─► FrameRing ─► FrameSynchronizer ◄────────────────────┘
                                  │
                          SessionRecorder ─► franka_telemetry.npz
                                  │
                     robot/franka/recording.export_session ─► schema v3 HDF5
```

问题：

1. `recorder` 通过 `arm.as_telemetry_dict()` 消费的是 **Franka 专属字段名**（`tcp_target`、`action_valid`）；
2. 采集层拿到的 `TelemetryBuffer` 子类是 `FrankaArmManager`，已隐含机型；
3. 缺失字段靠 `[0]*7` + `action_valid` 打补丁，与「缺失不写」冲突；
4. 导出由 `robot/franka/recording.py` 承担，HDF5 结构是 schema v3，与目标契约无关。

目标链路：

```text
RobotAdapter（每构型）
   │  declares(): 字段白名单子集
   │  report():   按标准名上报
   ▼
RecordingTelemetry（中间层，robot-agnostic）
   │  校验名称/形状/单位；按帧聚合；无字段即缺失
   ▼
FrameSynchronizer（相机主时间轴）
   ▼
SessionRecorder（无机型分支）
   ▼
Hdf5Exporter（统一 inhouse-hdf5-v2）
```

## 2. 分层与所有权

| 层 | 模块 | 职责 | 禁止 |
| --- | --- | --- | --- |
| 设备 | `robot/<type>/adapter.py` | 厂商通信、运动学、限位、夹爪、复位 | 不写文件、不懂 HDF5 |
| 契约 | `robot/core/recording_contract.py`（新增） | 字段白名单、形状/单位声明、ABC | 不含机型分支 |
| 中间层 | `robot/core/telemetry.py` → 扩展 | 按声明接收、校验、聚合、暴露标准视图 | 不推导缺失值 |
| 同步 | `app/capture/sync.py` | 相机主时间轴、软匹配 | 不造帧 |
| 录制 | `app/storage/recorder.py` | 原始会话落盘（MP4/npz/json） | 不含机型分支 |
| 导出 | `app/storage/hdf5_v2.py`（新增） | 目标键树、attrs、manifest | 不读厂商 SDK |

## 3. 字段契约（唯一真源）

```python
# robot/core/recording_contract.py（设计示意）

ACTION_FIELDS = {
    "eef_pose":       FieldSpec(shape=7, unit="m+quat_xyzw"),
    "joint_position": FieldSpec(shape="J", unit="rad"),
}
ACTION_SIDECAR = {"gripper": FieldSpec(shape=1, unit="m")}

OBSERVATION_FIELDS = {
    "joint_position": FieldSpec(shape="J", unit="rad",   required=True),
    "joint_velocity": FieldSpec(shape="J", unit="rad/s", required=False),
    "joint_effort":   FieldSpec(shape="J", unit="N*m",   required=False),
    "gripper":        FieldSpec(shape=1, unit="m",       required=True),
    "eef_pose":       FieldSpec(shape=7, unit="m+quat_xyzw", required=True),
}
```

规则：

- `FieldSpec.shape` 为 `int` 时固定；为 `"J"` 时由机器人描述 `dof` 决定。
- 适配器只能声明白名单中的键；越界在构造期抛 `ValueError`。
- `required=False` 的观测字段未声明 → 不创建数据集。
- action 全部未声明 → `has_action=false`，不创建 `/action`。

## 4. 标准上报格式

适配器每帧上报（`report()` 的返回值）：

```python
{
  "state": {
      "left": {"joint_position": [...7], "eef_pose": [...7], "gripper": [m], ...},
      "right": {...},
  },
  "action": {
      "left": {"eef_pose": [...7], "gripper": [m]},   # 仅声明的键
  },
  "wall_ts": 1.7e9,
  "monotonic_ts": 12345.6,
}
```

约束：

- 键名只能是白名单内的；
- 值必须是有限值的一维数组，长度与 `shape` 一致；
- 缺失的键直接不出现，**不填 None、不填 0**；
- `action` 中存在某侧，必须有该侧至少一个已声明字段。

## 5. 中间层行为

`RecordingTelemetry`：

| 方法 | 行为 |
| --- | --- |
| `declare(fields)` | 记录本构型声明的 action / observation 子集，校验白名单 |
| `accept(packet)` | 校验并追加到历史环形缓冲；非法包抛错，不静默丢 |
| `history()` | 供同步器按时间取最近样本 |
| `schema()` | 返回已声明字段，供 recorder/exporter 决定建哪些数据集 |

不做的事：

- 不补零、不复制上一帧；
- 不把请求目标 `TeleopTarget` 混入 action（action 只来自 adapter 实际下发值）；
- 不做机型分支。

## 6. 时间轴与缺失

- 主时间点 = center 相机同步帧的真实 `wall_ts`；
- 每帧从 `RecordingTelemetry.history()` 取最近样本（bracket + 容差规则沿用现行 `_match_wall_like_lr`）；
- 取不到样本 → 该帧该侧**不写**，不填零；
- 一帧内三路图像 + 至少一侧状态齐全才产生一行；
- 现行「缺相机生成黑图」必须移除，改为该帧不产出。

## 7. 会话中间产物（不变）

```text
<storage>/<task>/<YYYYMMDD_HHMMSS>/
├── left.mp4 center.mp4 right.mp4
├── audio.wav
├── timestamps.npy           # center.wall_ts
├── device_timestamps.npy
├── arm_telemetry.npz        # 标准字段名，按 side 前缀
├── signal_validity.json
└── meta.json
```

`arm_telemetry.npz` 键改为标准名：`<side>/<field>`，不再有 `tcp_target` / `action_valid`。

## 8. HDF5 v2 导出（目标）

```text
/                                  root attrs
├── timestamp                      (T,) float64
├── observation/
│   ├── state/<side>/<field>       (T, ...) float32
│   └── images/<cam>               (T,) vlen uint8 jpeg
├── action/<side>/<field>          (T, ...)  仅声明字段
└── language/                      本阶段不写
```

导出前置：

- `meta.json` 已结束且无 `recording_error`；
- `timestamps` 严格递增；
- 每路 MP4 解码帧数 == T；
- 已声明字段在 npz 中存在且形状正确。

不满足 → 导出失败并保留原始会话，不生成半成品 HDF5。

## 9. 与现行代码的迁移策略

保留：

- `FrameSynchronizer`（移除 black-frame 分支）；
- `app/capture/capture_service.py` 编排；
- `app/storage/sessions.py` 会话目录、索引；
- `app/teleop/*` 控制链路完全不动。

替换/新增：

| 动作 | 文件 |
| --- | --- |
| 新增字段契约 | `robot/core/recording_contract.py` |
| 扩展中间层 | `robot/core/telemetry.py` |
| 适配器声明与上报 | `robot/franka/adapter.py`、`robot/franka/telemetry.py` |
| recorder 去机型分支 | `app/storage/recorder.py` |
| 新增 v2 导出 | `app/storage/hdf5_v2.py` |
| 保留 v3 导出 | `robot/franka/recording.py`（仅历史/回放，不再用于新数据） |

## 10. 失败隔离

| 故障 | 行为 |
| --- | --- |
| 中间层收到非法包 | 抛错给调用方；该帧不写入；不污染后续 |
| 某侧遥测缺失 | 该帧该侧不写；不影响其他侧 |
| 相机某路缺帧 | 该帧不产出（不生成黑图） |
| 导出失败 | 保留原始会话，`h5_status=failed`，不写目标文件 |
| 磁盘/编码失败 | 沿用现有 recorder 错误路径；不阻塞控制 |

采集链路故障不得阻塞运动控制——沿用现行「控制进程不接触存储」的边界。

## 12. 本设计不做的事

- 不实现采集自检、拒收、`_SUCCESS` 封口；
- 不实现音频、language；
- 不实现真实 hold/暂停/失控时的 action 缺失策略；
- 不迁移历史 HDF5；
- 不改控制算法、限位、增益、安全参数。
