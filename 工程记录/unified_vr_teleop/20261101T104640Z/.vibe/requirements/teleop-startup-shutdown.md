## A. 采集页入口（confirmed）

- **A1** 采集页只保留两组操作：`启动相机 / 关闭相机`、`启动遥操作 / 关闭遥操作`。
- **A2** 两条链路互不耦合：启动遥操作不检查相机状态；关闭相机不影响遥操作；录制时相机缺失按现有"缺失信号警告、继续采集"规则处理。
- **A3** 对外始终只有一个"启动遥操作"按钮；点击后按**当前选中机型**从注册表取该构型的启动流程。新增构型只需注册自己的流程，不修改采集页。
- **A4** 现有"检查手柄 / 检查 FCI 反馈 / 运控预检 / 结束检查 / 启动执行"不再作为页面按钮暴露，只作为构型启动流程的内部阶段。

## B. 启动遥操作（confirmed，细节标注）

- **B1 结构**：启动流程 = 公共段 + 构型段，均为有序"阶段"列表；每阶段有名称、进度状态（待执行/进行中/完成/失败）、失败原因与缓解建议。
  - 公共段（平台实现一次）：启动 XR PC 服务 → 自动检测 USB 头显（adb）并连接 → 等待所选手柄数据新鲜。
  - 构型段（adapter 注册）：机械臂连接 → 自动检查/预检 → 进入执行。Franka：FCI/夹爪连接 → 反馈与手柄预检 → 执行；Piper：CAN 就绪 → 模式/IK 预检 → 执行；ARX：ROS2 链路同理。
- **B2 弹窗**：点击启动后弹出阶段式进度弹窗；弹窗提供"取消"。
- **B3 终点确认**（confirmed）：阶段推进到"就绪，等待确认进入执行"时停住；用户点击"确认"即为进入执行前的那一次安全确认（控制权已交接、区域清空），随后进入执行、弹窗关闭并提示"长按左菜单使能"。
- **B4 取消**：取消终止正在进行的阶段，并清理**本次启动已拉起的模块**（控制进程、机械臂 worker、XR 服务），不执行任何机械臂运动；取消后系统回到未启动状态。
- **B5 失败**：任一阶段失败即停在该阶段，弹窗直观显示失败原因与缓解建议；不自动回滚已成功阶段，不自动重试涉及机械臂运动的阶段；用户可取消（按 B4 清理）或修复后重新启动。
- **B6 不变量**：启动流程任何阶段不发出跟随目标；进入执行后机械臂仍处于保持，直到操作员长按菜单使能并松开再握 Grip。

## C. 关闭遥操作（confirmed，细节标注）

- **C1 弹窗**：点击"关闭遥操作"弹出询问"是否关闭遥操作并复位？"，三个按钮：`确定`（复位后关闭）、`关闭遥操作但不复位`、`取消`。
- **C2 关闭范围**：关闭 = 操作链路上每个模块都关闭并清理：退出控制进程 → 释放控制权并断开机械臂（Franka 结束 FCI 会话、关闭夹爪串口）→ 停止 XR 服务与头显连接。关闭后再次启动需重新走完整流程。
- **C3 确定（复位后关闭）**：先执行该构型的复位流程（Franka：hold → 闭爪 → 插值到复位姿态 → 开爪），复位**成功**后再按 C2 关闭。
- **C4 复位失败/取消**（confirmed）：复位失败或被取消时停止关闭流程，机械臂保持当前位置，弹窗显示原因；用户可选择"关闭遥操作但不复位"或取消。
- **C5 不复位关闭**：直接按 C2 关闭，机械臂保持当前位置；沿用已确认的"退出不自动复位"语义。
- **C6 录制中关闭**（confirmed）：若正在录制，先按现有规则结束并保存当前轨迹，再执行 C3/C5。

## D. 验收示例（Given–When–Then）

- Given 机型为 Franka、相机未启动，When 点击"启动遥操作"，Then 弹窗依次推进 XR 服务 → 头显 → Franka 连接 → 预检 → 等待确认，相机状态不影响任一阶段。
- Given 头显未插 USB，When 启动，Then 停在"检测头显"阶段，显示"未检测到 USB 头显，请连接数据线并在头显确认调试授权"，其余阶段不执行。
- Given 启动进行到 Franka 连接阶段，When 点击取消，Then 控制进程与 worker 被终止、XR 服务停止，机械臂无运动。
- Given 执行中，When 点击"关闭遥操作"→"确定"，Then 先完成复位再依次关闭控制、机械臂、XR；When 选择"关闭但不复位"，Then 机械臂保持当前位置后依次关闭。

## F. 机械臂模型显示（confirmed）

- **F1**（confirmed）系统维护全局机型上下文（机型、选中臂、URDF 资源、关节数、传输类型等），显示内容只由该上下文驱动；上下文变化时显示自动变化。
- **F2**（confirmed）URDF 显示使用**一个共享的显示对象/模块**，页面不各自创建和维护 viewer；该对象按机型上下文选择模型（Franka→fr3.urdf，Piper→piper_description.urdf）。
- **F3**（confirmed）模型来源规则：采集页实时预览跟随**当前选中机型**；回放页单独处理——跟随**当前回放会话数据中记录的机型**（可回放不同机型数据），与当前选中机型无关；元数据缺失时回退到当前机型并提示。`selected_sides` 只决定哪些 pane 收到姿态数据，不决定 pane 数量（见 F4′）。
- **F4′ 固定视图布局，渲染与数据解耦（v1.2，confirmed，取代原 F4）**：
  - **相机视图**：采集页与回放页都固定 3 个 pane（左/中/右）；单臂/双臂操作模式不改变 pane 数量。某一路无信号时，该 pane 保留并显示“相机信号缺失”，不删除、不合并、不重排。
  - **URDF 预览**：采集页与回放页都使用固定 pane 数量（左右两个）；单臂操作、回放单臂录制数据都不减少 pane，也不改变页面布局。

- **F5**（evidence，v1.2 已解决）早期 viewer 默认加载 Piper、页面构建时不知机型；现由 F1/F2 的全局机型上下文与单一 viewer 解决。固定 pane 数量由 F4′ 明确，不再视为缺陷。

## I. 执行中异常与复位语义（confirmed）

统一思维模型：**所有机械臂侧"流程"（启动、健康检查、复位、关闭、故障恢复）都是 adapter 向注册表注册的阶段序列，由同一个公共流程执行器运行、同一个阶段式弹窗展示；公共层只负责调度、显示与操作员选项，判定规则随流程由 adapter 决定。**

- **I1 流程统一**：adapter 注册 5 类流程：`startup`、`health_check`、`reset`、`shutdown`、`recover`。每类都是阶段列表（名称/状态/原因/缓解），公共执行器逐阶段运行并驱动弹窗；可取消；失败停在该阶段。
- **I2 复位 = 流程**：复位（A+X 空闲、设置页高级区、关闭弹窗"确定"三种触发）走 `reset` 流程并弹出阶段进度（Franka：保持 → 闭合夹爪 → 运动到复位姿态 → 张开夹爪 → 校验到位）。复位期间**各阶段的监测判定由 adapter 定义**：夹爪 I/O 阶段暂停夹爪新鲜度判定，机械臂反馈判定全程保留。取消 = 短按菜单或弹窗"取消"，机械臂保持。缺陷归属：现行实现把公共 250ms 夹爪判定套在复位上，导致误判→worker hold→复位取消、VR 失去使能。
- **I3 故障 = 统一状态 + 一个弹窗**：执行中任一监测触发（目标流 >200ms、心跳 >500ms、反馈超时/写入失败、VR 失联 >150ms 且处于使能）→ 机械臂立即保持，全局控制状态进入 `faulted(原因)`；显示层只订阅该状态：顶部红条 + 一个故障弹窗，列出原因、缓解，三个选项：`自动恢复`（运行该构型注册的 `recover` 流程：Franka 为 重新预检 → 重新进入执行；失败则落回故障态）、`关闭遥操作`（走 C 节关闭弹窗）、`仅保持`（关闭弹窗，机械臂保持，稍后再处理）。
- **I4 VR 失联区分**：仅手柄数据不新鲜且未发生机械臂故障时，不进入 `faulted`，而是 `disabled(VR 失联)`：保持并解除使能，数据恢复后操作员重新长按菜单即可，不弹故障弹窗（现有行为保留，但状态文案统一）。
- **I5 复位完成（v1.1）**：操作员显式触发的复位成功后统一恢复 VR 使能，无需再次长按菜单；仍必须松开再握 Grip 才跟随。Y 保存或 X 丢弃一条录制后自动提交复位；录制中 A+X = 丢弃本条并复位，空闲 A+X = 复位。
- **I6 不变量**：公共层永不自行发起运动；所有运动类流程（`reset`、`recover` 中的执行阶段）只能由操作员显式触发并带一次确认（复位：触发即视为确认；recover：弹窗按钮即确认）；流程执行器在任何失败路径上先调用 adapter `hold`。
- **I8 幂等流程（v1.4）**：所有流程阶段执行前先检测目标状态，已完成则记为成功并跳过；流程可重入、可重复触发，不得因重复执行破坏已建立的连接或重复触发运动。
- **I7 显示绑定**：控制状态（`idle / starting / ready / enabled / following / resetting / disabled / faulted / closing`）是全局上下文的一部分，采集页状态条、启动/关闭/故障弹窗都只由它驱动，不再各页面各自判断。
