# 数据采集链路：端点驱动数据流图（现行实现）

- 日期：2026-11-01
- 代码版本：`unified_vr_teleop_franka@feat/franka`（未真机验证）
- 对照基线：`hdf5-recording-format` v1.2
- 画法：从 **PICO** 和 **相机** 两个端点出发；`✂` 标出数据在此被记录/分叉的节点；分支右侧是该分支经过的中间节点与最终落盘位置。

---

## A. PICO 端点：从手柄到 action

```text
【PICO 硬件】
  头显 pose / 手柄 pose / grip 模拟量 / trigger / A B X Y / 摇杆 / 菜单
        │  ≈50Hz
        ▼
【XR PC Service】xrobotoolkit_sdk（独立进程，非本仓库）
        ▼
【receiver.py::receive_loop】子进程
  get_controller_snapshot() + get_headset_pose()
        ▼
  mp.Queue(2)  ──►  RecoveringInput.poll()
                     └─ StreamWatchdog：stamp/age → fresh
        ▼
【eef_runtime.run()】主循环（公共层，不知道机器人型号）
  ├─ PoseClutch.target(samples, measured, fresh)
  │     grip 锚定 → 相对位姿 → 机械臂基座系
  │     trigger → 夹爪开口 = (1-trigger) × max_opening
  │     ✂ 不落盘
  │
  ├─ teleop_target()  ← ★ TeleopTarget（请求目标，不是最终 action）
  │     {side, tcp_pose, gripper_position, sequence,
  │      monotonic_ts, source:'human', frame:'robot_base'}
  │     ✂ 不落盘
  │
  └─ 按键 ──► ControlEvents.emit()
                 │
                 ✂ 记录点 ①（事件，不是帧数据）
                 ▼
           runtime/data/control-events.jsonl
                 ▼
           RecordingSession（web 进程，50ms 轮询）
                 ▼
           CaptureService.start_recording / stop_recording
                 → 决定 episode 边界、save/discard
        ▼
【UNIX socket】runtime/data/franka.sock（JSON 行）
   DeviceWorker.handle('targets')
     ├─ 租约 500ms / 序号递增 / 时效 ≤150ms
     ▼
【FrankaAdapter.apply_targets】
   validate_target()：四元数归一化、TCP 工作空间限位、夹爪量程
     ▼
【FrankaController.send(pose, opening)】
   ├─ arm.move_tcp_pose() ─► Franky ─► FCI ─► Franka 机械臂
   ├─ gripper.set_target() ─► Robotiq Modbus ─► 夹爪
   └─ ★ last_action = {tcp_pose, gripper, issued_wall_ts, source}
            │
            ✂ 记录点 ②（真正的 action：实际提交给驱动的控制参考）
            │  注意：不是 PICO 的位姿，也不是 TeleopTarget 原值
            │        —— 经过限位与工作空间裁剪后、真正下发的那一个
            ▼
        等待下一次回读（feedback）
```

### A 分支：action 如何到磁盘

```text
last_action
   ▼
FrankaController.feedback()   ← 仅当 tracking=True 才带上 action
   ▼
FrankaAdapter.feedback() → {side: {...}}
   ▼
DeviceWorker.tick() → status()     ★ 记录点 ②'：打包成反馈包
   ▼  JSON over UNIX socket
Client.request()  ←  FrankaArmManager._poll()  200Hz
   ▼
FrankaSample.from_packet()  校验新鲜度 ≤ feedback_timeout
   ▼
TelemetryBuffer.history（环形，≈1.5s）
   ▼
FrameSynchronizer.arm 匹配（对 center.wall_ts，50ms 容差）
   ▼
SyncedTriplet.arm
   ▼
SessionRecorder.write_triplet() → FrankaSample.as_telemetry_dict()
   │   每侧 11 字段：joint_position(7) joint_velocity(7) joint_effort(7)
   │   tcp_pose(7) gripper_position(1)
   │   tcp_target(7) gripper_target(1) action_valid gripper_action_valid
   │   issued_wall_ts sample_wall_ts
   │   ✗ 丢弃 source（command/reset 不可区分）
   ▼
franka_telemetry.npz
   ▼
export_session() → /robot/<side>/tcp_target, /robot/<side>/gripper_target
                → /action, /action_valid
```

## B. 机器人端点：实测状态

```text
【Franka 机械臂 + Robotiq 夹爪】
        ▼
Franky SDK get_state() / gripper.position
        ▼
【FrankaController.feedback()】
   ├─ ★ joint_position / joint_velocity / joint_effort（7 轴）
   ├─ ★ tcp_pose（7 维 x y z qx qy qz qw）
   ├─ ★ gripper_position（米）
   └─ ★ wall_ts / monotonic_ts
        ✂ 记录点 ③（实测状态，绝不冒充 action）
        ▼
（与 A 分支共用同一条回程）
DeviceWorker → Client → FrankaArmManager → TelemetryBuffer
        ▼
FrameSynchronizer → SyncedTriplet.arm → recorder
        ▼
franka_telemetry.npz
        ▼
/robot/<side>/joint_* tcp_pose gripper_position
→ /observations/{qpos, qvel, effort, eef_pose, gripper}
```

## C. 相机端点：三路图像

```text
【三路相机】left / center / right
        ▼
camera/<type>/driver.py（uvc / zed / orbbec / realsense）
   JPEG 字节 + wall_ts + device_ts_ms + clock（host｜device）
        ▼
MultiCameraManager → FrameRing（每路独立环形缓冲）
        ▼
FrameSynchronizer（单线程）
   ├─ center 帧推进，延迟 lag_ms=400ms
   ├─ L/R 最近邻 + 时间容差 + bracket（前后邻帧都在）
   ├─ wall 模式（默认）或 device 模式（三路均有设备时钟且探针通过）
   └─ ★ SyncedTriplet.wall_ts = center.wall_ts  ← 主时间轴来源
        ▼
SyncedTriplet{left, center, right, wall_ts, aligned, missing_roles}
        ▼
SessionRecorder.write_triplet()
   ├─ ★ wall_ts ──────────────► timestamps.npy
   ├─ ★ center.device_ts_ms ──► device_timestamps.npy
   ├─ ★ 有效位 ───────────────► signal_validity.json（每帧一行）
   └─ ★ 三路 JPEG ──► 每路一个 ffmpeg（MJPEG→H.264）
                          ▼
                   left.mp4 / center.mp4 / right.mp4
```

## D. 音频端点

   ▼

## E. 汇总点：一次停止后的产物

```text
<storage_root>/<task>/<YYYYMMDD_HHMMSS>/
├── left.mp4  center.mp4  right.mp4      ← C 的 JPEG 编码结果（恒定帧率）
├── audio.wav                            ← D
├── timestamps.npy                       ← C 的 center.wall_ts（唯一真实时间轴）
├── device_timestamps.npy                ← C 的中心相机设备时钟
├── franka_telemetry.npz                 ← A 的 action + B 的实测状态（逐帧 11 字段/侧）
├── signal_validity.json                 ← 每帧哪路缺失
└── meta.json                            ← 任务、相机序列号、同步统计、掉帧、错误
```

## F. 从汇总点到最终落盘

```text
meta.json（recording=false）
   ▼  H5ConvertQueue（后台单线程）
export_session_to_h5()
   ├─ 闸门：signal_validity 有缺 arm 或缺侧 → 直接拒绝导出
   ▼
robot/franka/recording.export_session()
   ├─ load()：timestamps 严格递增；frame_time 与 timestamps 一致
   │           每侧 11 字段形状 (T,…)；sample_wall_ts 与 timestamp 偏差 ≤50ms
   ├─ ffmpeg 解码三路 MP4 → JPEG 序列，要求每路帧数 == T
   ▼
episode_<idx>_<stamp>.hdf5   ← .tmp 写完后原子 rename
   ├── /robot/timestamp
   ├── /robot/<side>/*（11 字段）
   ├── /observations/{qpos,qvel,effort,eef_pose,gripper}
   ├── /action  [tcp_target(7)+gripper(1)] × 侧
   ├── /action_valid
   ├── /observations/images/{cam_left_wrist,cam_high,cam_right_wrist}
   ├── /audio/pcm
   └── attrs(robot_type, schema_version=3, num_frames, fps, robot_spec_json)
   ▼  UploadQueue
远端存储（无 manifest、无 MD5、无 _SUCCESS —— 新基线尚未实现）
```

## G. 记录点清单

| 记录点 | 节点 | 记录内容 | 最终路径 |
| --- | --- | --- | --- |
| ① | `eef_runtime` 按键 | 开始/保存/丢弃/复位事件 | `control-events.jsonl`，**不进 HDF5** |
| ② | `FrankaController.send()` 的 `last_action` | 实际下发的 EEF + 夹爪 | `/action/*`（v1.2 目标：`action/<side>/eef_pose`、`gripper`） |
| ③ | `FrankaController.feedback()` | 实测关节/位姿/夹爪 | `/observation/state/<side>/*` |
| ④ | 相机驱动 `CameraFrame` | JPEG + wall_ts | `/observation/images/<cam>` |
| ⑤ | `FrameSynchronizer` | center.wall_ts（主时间轴）、对齐/缺失标记 | `/timestamp` |
| ⑥ | `AudioRecorder` | PCM | `/language/audio_pcm`（目标）或 `/audio/pcm`（现行） |

## H. 明确不会被记录的数据

- **PICO 原始量**：头显 pose、手柄 pose、grip 模拟值、trigger 模拟值、headset_pose —— 全部只用于实时映射。
- **TeleopTarget**（请求目标）：只在内存和 socket 上流转，`source='human'`。
- **PoseClutch 内部状态**：锚点、标定矩阵、阈值。
- **同步中间量**：`arm_dt_ms`、bracket 等待次数、buffer 深度 —— 只进 `meta.json` 和日志。
- **action 的 `source`**（command / reset）：在 `last_action` 里有，`as_telemetry_dict()` 丢弃。
- **相机内参/外参**：当前完全未采集。
- **IK/关节目标**：Franka 走笛卡尔控制，无此层；未来关节型构型会新增这一节点。

## I. 与 v1.2 的冲突点（改造位置）

| 节点 | 现行 | v1.2 |
| --- | --- | --- |
| `sync._partial_once` | 缺相机时生成**黑色 JPEG** 顶替 | 缺失就不写该帧 |
| `telemetry.as_telemetry_dict` | 无 action 时写 `[0]*7` + `action_valid=false` | 不写，禁止全 0 占位 |
| `recorder.write_triplet` | 图像照写、遥测可缺，靠导出拒收兜底 | 逐帧一致，缺失即不写 |
| `franka/recording.export_session` | schema v3：`/robot`、`/observations`、拼接 `/action` | `/timestamp`、`/observation`、分侧 `action/<side>` |
| 汇总点之后 | 无 batch / manifest / MD5 / `_SUCCESS` | R9、R10 全流程 |
