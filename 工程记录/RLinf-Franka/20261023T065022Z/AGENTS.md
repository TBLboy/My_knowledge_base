### 架构、环境与设备

- 控制入口为 `robot_capture_franka/franka/`：网页通过 supervisor/本地 IPC 调用独立 worker；`RigBackend` 管理所选侧的独立后端，复用本地 `franka/drivers/` Franky、Robotiq、Pico 驱动。不得另建绕过 worker 的硬件控制链路，也不得让多个进程争抢同一机器人。
- 工作台用 `robot_capture_franka/.venv`；worker/Pico 发布器用 `.venv-control`，均为 Python 3.11。当前控制依赖固定 `franky-control==2.0.0`；不得混用系统 Python、Vibe 环境或旧 RLinf 虚拟环境。依赖默认使用国内镜像。
- 真机控制必须核对实际实时内核、权限、memlock 限额及启动进程继承值，不凭历史记录推定。`realtime_config=enforce` 不得降为 ignore 绕过。
- 设备映射以 `config/franka-rig.json` 为准：左臂 `172.16.0.2`、右臂 `172.16.0.3`。Robotiq 用 `/dev/serial/by-id/` 稳定串口路径，不用 `ttyUSBN` 临时编号。
- 相机顺序固定左腕／全局／右腕：两台 ZED-M 腕相机通过已确认的 USB 物理路径区分，ZED 2i 为全局视角。UVC 无深度；使用 USB 3.0，保持腕相机插口与 hub 拓扑稳定。某相机仅有 HID、没有视频节点时，不视为相机已就绪。
- UI 启动入口为 `bash robot_capture_franka/start.sh`（在工作区根运行），默认端口 5000。启动网页不等于启动机器人；控制会话仅由操作者发起。重启前确认录制、worker 和发布器状态，不强杀正在控制机器人的进程；HTTP 200 只证明网页可用。

### 单／双臂行为与数据边界

- 支持左臂、右臂、双臂模式；切换前结束录制、停止相机预览、退出遥操并完成清理。不要从基础配置的旧右臂默认值推断当前模式；实际投影配置由 rig 和所选模式共同生成。
- 每侧 grip/trigger 控制对应机械臂／夹爪；所选模式下左菜单负责启用／暂停，右摇杆点击负责标定。键位与长短按语义以当前源码为准，不套用旧 RLinf 键盘规则。
- 复位只作用于所选机械臂；保存复位位姿时一次读取并原子保存全部所选侧。禁止将右臂目标复制为左臂目标。姿态窗口中心随各自保存的复位姿态同步，位置盒不漂移；现有宽工作区不是可靠安全保护，不得再放宽。
- 选中侧运行故障只暂停该侧，但结束整条录制并保留错误，不自动复位。双臂整体启用必须两侧就绪。采集和回放固定显示左右两个独立、水平并排的 URDF 视图，未选侧不隐藏，有哪侧数据才驱动哪侧。
- 左／右／双模式分别使用左腕+全局、全局+右腕、全部三相机，并仅保存所选机器人数据。新数据使用侧前缀 NPZ 与 HDF5 `robot/left`、`robot/right`；历史无侧别单臂数据按右臂关联，不复制到两侧，不伪造缺失数据。
- 保留 `recordings/`、现有索引及 NAS 设置。上传目标为 `/mnt/nas/forge/franka/raw`；存储、上传配置不随控制适配而改动。数据结构完整、离线测试通过不等于真机运动安全或物理同步精度已验收。
