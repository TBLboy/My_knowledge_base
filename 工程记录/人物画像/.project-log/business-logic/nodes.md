# Business Logic Nodes

## P0: Real Goal Defined

- Status: draft
- State: 一个真实工作/学习/职业问题及成功标准已被明确。
- Inputs: 本人需求、项目上下文、时间/资源约束。
- Outputs: 问题定义、优先级、验收标准。
- Verification: 本人确认问题值得投入且边界清楚。

## P1: Evidence And Constraints Collected

- Status: active
- State: 已收集解决当前问题所需的项目事实、能力资产、约束与未知项。
- Inputs: 项目 `.project-log`、代码、数据、本人自述、可信外部资料。
- Outputs: 事实清单、假设清单、开放问题。
- Verification: 事实、推断和未知项清晰分离。

## P2: Work Mode Selected

- Status: draft
- State: 已选择与问题匹配的工作模式和最小必要 Skill 组合。
- Inputs: P1 的事实、目标和约束。
- Outputs: 执行方案、Skill/工具边界、验证门。
- Verification: 每个步骤都有目标、产物和停止条件。

## P3: Work Executed

- Status: draft
- State: 学习、调研、设计、实现、实验或验证正在按已选模式执行。
- Inputs: P2 的执行方案。
- Outputs: 代码、实验结果、调研报告、设计、测试或实机证据。
- Verification: 运行对应测试、数据检查、仿真、浏览器验收或实机验收。

## P4: Project Truth Recorded

- Status: draft
- State: 关键事实、业务逻辑、决策、失败与验证结果已写入项目记录。
- Inputs: P3 结果。
- Outputs: 更新后的 `.project-log` 和必要的代码/文档证据。
- Verification: 项目可由新的 AI/协作者依据记录恢复上下文，不需猜测关键逻辑。

## P5: Reusable Knowledge Distilled

- Status: draft
- State: 已验证的跨项目经验被抽象为候选知识或 Skill 改进。
- Inputs: P4 的项目记录和证据。
- Outputs: 个人知识库候选项、Skill 改进建议、反模式记录。
- Verification: 每项都有来源、适用条件和置信度；未验证猜测不进入正式知识库。

## P6: Personal Strategy Updated

- Status: draft
- State: 新知识被映射到个人能力、作品、职业路径与下一轮优先级。
- Inputs: P5 的可复用知识、现实职业反馈。
- Outputs: 人物画像增量、能力缺口、下一周期目标。
- Verification: 下一行动能明确服务于主线目标，而非只增加忙碌度。
