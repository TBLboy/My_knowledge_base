# Main Business Logic

## Status

- Current main path status: Draft
- Scope: 个人 AI 工作架构与人物画像维护，不改变其他项目的业务逻辑。

## Main Path

```text
P0 真实目标/问题明确
 -> P1 收集当前事实、约束和已有资产
 -> P2 选择工作模式与对应 Skill
 -> P3 执行学习/调研/设计/实现/验证
 -> P4 记录项目事实、决策、证据和失败
 -> P5 复盘并蒸馏可复用知识
 -> P6 更新人物画像、能力地图和下一轮优先级
 -> P0
```

## Path Summary

- P0: 明确一个真实目标、决策或问题，以及成功标准。
- P1: 从项目记录、代码、数据、外部资料和本人确认中收集事实；不以猜测补缺。
- P2: 决定是直接工程、方案调研、深度研究、项目记录、知识蒸馏、上下文交接或其他模式；只加载必要 Skill。
- P3: 在明确约束下执行，并在适用时运行测试、数据分析、仿真、浏览器验收或实机验证。
- P4: 将稳定业务逻辑、关键决策、证据、失败和未验证项写入对应项目 `.project-log`。
- P5: 将已验证且跨项目可复用的经验，经审阅后进入个人知识库或 Skill 规则；不将项目噪声直接入库。
- P6: 将新证据映射为能力提升、能力缺口、职业资产和下一个最重要行动，更新人物画像。

## Implementation Priority

- Current target node: P1
- Current target edge: P1 -> P2
- Current task: 盘点当前 AI 工作方式和现有 Skills，确定架构首先解决的真实问题。

## Stable Assumptions

- 人负责目标选择、价值判断、安全责任和最终验收；AI 负责加速信息处理、结构化、实现、审查和记录。
- 关键工程/研究结论必须经过适用的验证门，不能因模型表述自信而升级为事实。
- 项目 `.project-log` 是项目事实与业务逻辑的来源；个人知识库只保存抽象后的可复用规则；人物画像只保存个人发展相关的证据和判断。
- 新 Skill 默认是候选分支，只有解决反复出现的真实问题、边界清晰且维护成本合理时才进入长期体系。
