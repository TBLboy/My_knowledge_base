# 项目经历提取与简历凝练工作流

- **记录日期：**2026-08-16
- **状态：**已规划，等待用户开始并提供工作经历材料。
- **目标：**以真实工作/项目经历为事实源，逐步提取、确认、凝练并优化为可直接放入简历的项目经历条目。

## 执行阶段

1. **信息提取**
   - 从用户提供的工作记录、项目材料、代码、图片、奖项或说明中提取项目背景、任务、个人职责、技术动作、协作关系、结果和证据。
   - 将“已确认事实”“用户主观表述”“推断”“未知/待补充数据”分开记录；不把包装性语言当作事实。

2. **第一轮讨论与确认**
   - 针对每个项目确认真正的个人贡献、难点、技术方案、成果边界和可公开程度。
   - 优先补齐量化信息：指标、性能、规模、周期、排名、用户/团队影响、成本或效率变化。

3. **形成项目经历草稿**
   - 输出适合简历阅读的初版条目：项目名称、时间、角色、技术栈，以及 2–4 条成果导向描述。
   - 草稿必须标注为“待讨论”，避免未确认数据进入最终版本。

4. **第二轮讨论与优化**
   - 根据目标岗位和你的反馈，调整技术深度、业务表达、关键词密度、条目长度和优先级。
   - 删除空泛表述，保留与岗位强相关且能经得起追问的内容。

5. **最终简历版凝练**
   - 仅在事实、措辞与数据经你确认后，生成可直接放进简历的最终项目经历版本。
   - 必要时另输出针对不同岗位的定制版本，例如机器人/具身智能版与大模型应用版。

## 约束

- 允许专业化表达、结构优化和合理凸显价值；不捏造未发生的项目、职责、指标、奖项、学历或技术成果。
- 没有量化数据时，先使用真实的过程性成果描述，或以待确认占位符标注。
- 最终内容应做到：一眼体现岗位相关性、能被面试追问、与实际材料一致。

## 第一阶段输入清单

- 工作经历或项目的原始叙述/工作记录
- 项目时间、角色、团队规模与个人分工
- 用过的技术、工具、平台与关键实现
- 遇到的难点、采取的动作、最终结果
- 可证明材料：代码、文档、截图、演示、论文、奖项或数据
- 拟投递岗位与岗位描述（如已有）

## 用户确认的包装与美化原则

### 背景约束

- 用户当前实习预计于 **2026-10-01** 结束；截至 2026-08-16，秋招已经开始。
- 简历工作需要优先服务于近期投递和面试，而不是只做静态文字润色。

### 用户认可的表达策略

用户明确认可在真实经历基础上进行适度的岗位化重构和优势突出，包括：

1. 根据目标岗位调整项目叙事重点，而不是机械复述原始组织架构。
2. 将个人实际负责的关键模块、工作流或阶段性任务提炼为个人主导成果。
3. 对零散贡献进行结构化整合，突出个人在需求分析、方案设计、技术实现、推进落地或结果验证中的作用。
4. 选择有事实依据的优势维度表达，例如成绩提升幅度、效率提升、问题解决难度、项目影响范围，而不只呈现绝对排名或普通参与身份。
5. 用面试可解释、可复盘的完整叙事呈现个人能力：背景、目标、判断、动作、技术细节、协作边界和结果。

### 不可越过的边界

- 不捏造学历、公司、项目、奖项、任职经历或完全不存在的工作内容。
- 不凭空制造指标、排名、用户数、性能提升或管理权限。
- 不把完全没有参与的项目包装成个人经历。
- 对“负责人”“主导”“最高”“提升幅度最大”等强表述，必须保留可解释的事实依据；必要时将范围限定为本人负责的模块、阶段或工作流。
- 不能为了通过 HR 筛选而形成面试无法自洽的叙事。

### 后续执行口径

后续简历重构允许并鼓励进行强表达、岗位化包装和扬长避短，但每条最终表述都要同时满足：**岗位相关、事实可追溯、面试可展开、边界可解释**。初稿可以提出更激进的表达方案，再由用户确认实际支撑程度。
